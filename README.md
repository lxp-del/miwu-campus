> 基于 **Java + Spring Boot + Vue3 / uni-app + LangChain4j + 大模型** 构建的校园二手交易平台，面向高校学生提供商品交易、实时沟通、校园社区、AI 智能服务及校园公益等功能。

##  项目简介

**觅物**是一款面向高校校园场景设计的二手交易平台。

针对传统校园二手交易中存在的：

* 商品信息分散
* 买卖双方沟通成本较高
* 商品描述质量参差不齐
* 交易信息缺乏统一管理
* 校园用户身份真实性难以保证
* 用户寻找目标商品效率较低

等问题，平台将 **二手商品交易、校园社区、实时通信、AI 智能服务、个性化推荐及校园公益** 进行整合。

用户完成校园身份认证后，可以发布、浏览、搜索及购买二手商品，并通过实时私信与卖家沟通；同时利用大模型和视觉模型辅助完成商品分析、描述生成、智能估价、自然语言查询及业务知识问答。

#  核心功能

## 1.  用户注册与身份认证

面向校园用户设计用户认证机制。

主要功能：

* 学生信息认证
* 用户注册 / 登录
* 用户信息维护
* 登录状态管理
* 接口权限控制
* 个人资料管理

后端使用 **Sa-Token** 实现登录认证及接口权限控制，并结合业务身份进行权限校验。

---

## 2.  二手商品管理

围绕校园二手交易场景设计完整的商品业务流程。

### 商品发布

用户可以：

* 上传商品图片
* 填写商品标题
* 编写商品描述
* 设置商品价格
* 设置商品分类
* 发布二手商品

商品图片通过 **阿里云 OSS** 进行对象存储，并将 OSS 地址与商品业务数据进行关联。

### 商品管理

支持：

* 商品列表
* 商品详情
* 商品搜索
* 商品上下架
* 商品修改
* 商品撤回
* 商品状态管理
* 商品评论

商品从发布到交易完成形成完整的业务流程。

---

## 3.  订单与交易

围绕商品购买过程设计订单业务。

基本业务流程：

```text
浏览商品
   ↓
查看商品详情
   ↓
发起购买
   ↓
创建订单
   ↓
订单状态流转
   ↓
交易完成
```

后端通过 **Spring Boot + MyBatis-Plus** 实现用户、商品、订单等核心业务模块，并通过事务保证订单相关数据的一致性。

---

## 4.  WebSocket 实时私信

平台提供买卖双方实时沟通功能。

采用 **WebSocket** 建立客户端与服务端之间的长连接：

```text
用户 A
  │
  │ WebSocket
  ▼
服务器
  │
  │ 消息路由
  ▼
用户 B
```

主要实现：

* 用户连接管理
* 用户身份绑定
* 指定用户消息路由
* 实时消息推送
* 买卖双方私信沟通

相比传统 HTTP 轮询方式，可以减少客户端反复请求，实现更加实时的消息交互。

#  AI 智能能力

项目并不是简单地调用一次大模型 API，而是将 AI 能力与平台业务进行结合。

整体 AI 业务链路：

```text
用户自然语言
      │
      ▼
   AI 对话层
      │
      ▼
  用户意图理解
      │
      ▼
 Tool Calling
      │
 ┌────┼───────────┐
 ▼    ▼           ▼
商品查询  业务数据查询  其他工具
 │    │
 └────┼───────────┘
      ▼
业务系统返回数据
      │
      ▼
   LLM 整理回答
      │
      ▼
   用户获得结果
```

---

## 5. 🧠 AI 对话与业务数据查询

基于 **LangChain4j** 构建 AI 对话能力。

参考 LangChain4j 官方 Examples 中 **AI Service、Tool Calling、RAG** 等实现思路，将平台业务能力封装成 AI 可以调用的工具。

例如：

```text
用户：
“帮我找一下 500 元以内的二手 iPad”

        ↓

AI 理解用户需求

        ↓

调用商品查询 Tool

        ↓

后端查询商品数据

        ↓

返回符合条件的商品

        ↓

AI 整理结果

        ↓

向用户返回商品信息
```

### Tool Calling

将部分业务能力封装为 Tool，例如：

```text
商品查询 Tool
      ↓
根据关键词、价格、分类等条件查询商品

业务数据查询 Tool
      ↓
访问平台业务数据

订单相关 Tool
      ↓
查询用户相关业务信息
```

这样可以让 AI 不仅回答固定知识，还能够根据用户需求调用后端真实业务能力。

---

## 6. 📚 RAG 知识检索

在 AI 对话基础上引入 RAG，使 AI 能够结合平台业务知识进行回答。

基本流程：

```text
用户问题
   ↓
问题理解
   ↓
知识检索
   ↓
获取相关业务知识
   ↓
构造 Prompt
   ↓
LLM
   ↓
生成回答
```

RAG 主要用于：

* 平台业务规则问答
* 商品相关知识问答
* 平台使用说明
* 商品推荐辅助
* 基于业务知识的智能咨询

通过检索外部知识，再交由大模型生成回答，减少完全依赖模型自身知识带来的信息缺失问题。

# 👁️ AI 商品图片分析

项目接入视觉模型，对商品图片进行分析。

技术：

* **Qwen-VL-Max**
* **DeepSeek API**

用户上传商品图片后，可以利用视觉模型对图片中的商品进行分析，例如：

```text
商品图片
   ↓
视觉模型
   ↓
识别商品信息
   ↓
提取商品特征
   ↓
辅助生成商品描述
   ↓
辅助商品估价
```

主要用于：

* 商品图片分析
* 商品信息提取
* 商品描述辅助生成
* 商品价格估算

减少用户发布商品时重复填写商品信息的成本。

# 🔎 AI 智能商品查询

除了传统关键词搜索，平台支持通过自然语言描述需求。

例如用户输入：

> “帮我找一个适合考研使用的二手平板，预算 1000 元以内。”

AI 可以分析：

```text
用户需求
 ↓
商品类型：平板
 ↓
使用场景：学习 / 考研
 ↓
价格范围：≤ 1000
 ↓
调用商品查询能力
 ↓
获取商品数据
 ↓
AI 整理结果
 ↓
返回推荐商品
```

这种方式将：

**自然语言 → 业务条件 → 后端查询 → AI 结果整理**

连接起来，使 AI 对话能够真正参与平台业务。

# 🔐 安全与工程实践

项目在开发过程中重点考虑了业务接口的安全性和数据一致性。

### 接口权限

基于 Sa-Token：

```text
用户登录
   ↓
获取登录状态
   ↓
访问业务接口
   ↓
身份校验
   ↓
业务权限校验
   ↓
执行业务操作
```

避免用户直接操作其他用户的商品、订单及个人数据。

### 事务控制

对于订单创建、商品状态变化等涉及多个业务数据修改的操作，通过事务保证相关数据的一致性。

### Redis 缓存

针对高频访问的商品及业务数据引入 Redis，减少重复数据库查询。

# 🛠️ 本地运行

## 环境要求

```text
JDK 17+
Maven 3.8+
MySQL 8+
Redis 6+
Node.js
```

## 后端配置

修改数据库、Redis、OSS 及 AI 服务相关配置：

```yaml
spring:
  datasource:
    url: jdbc:mysql://localhost:3306/xxx
    username: root
    password: ******

  data:
    redis:
      host: localhost
      port: 6379
```

根据实际项目配置补充：

```text
DeepSeek API Key
Qwen API Key
阿里云 OSS 配置
支付宝沙箱配置
```

## 启动后端

```bash
mvn clean install

mvn spring-boot:run
```

或者直接运行项目启动类。

## 启动前端

```bash
npm install

npm run dev
```

具体启动命令根据实际 uni-app / Vue3 项目配置进行调整。
